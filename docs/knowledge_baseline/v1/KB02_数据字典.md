# KB02｜DATA-4.1 数据字典

> 知识域：`data_dictionary`  
> 适用场景：`charging_ops`、`sales_ops`  
> 版本：`1.0.0`  
> 数据库：PostgreSQL  
> 当前 Schema Catalog：13 张受治理表、141 个字段、19 条关系。

## 1. 数据分层

当前业务链路采用：

`公开源快照 → raw → staging → core → semantic → API → UI / ChatBI / RAG`

各层职责：

- **lineage**：来源、许可、不可变快照、摄取运行、质量结果；
- **raw**：保留源记录或无损源字段，禁止直接供普通业务查询；
- **staging**：标准化类型、时间、主键和字段名称；
- **core**：业务事实与活动经营数据；
- **semantic**：受治理指标定义和语义模型；
- **API/UI**：只读取经过发布和权限控制的数据。

## 2. 数据分类标记

为避免混淆，知识与数据治理统一使用以下三类字段来源：

- `SOURCE`：公开数据源原始提供；
- `DERIVED`：由源字段依据确定规则计算；
- `BUSINESS_ASSUMPTION`：源数据缺失但为业务分析所需，由显式版本化规则提供。

任何 `DERIVED` / `BUSINESS_ASSUMPTION` 字段必须保留规则版本、依据和运行标识，不能描述为源数据原生字段。

## 3. DATA-4.1 受治理表

### 3.1 `open_data_source`

层级：lineage  
用途：登记公开数据源及许可。

关键字段：

| 字段 | 含义 |
|---|---|
| `source_id` | 来源唯一标识 |
| `source_name` | 来源名称 |
| `source_url` | 来源地址 |
| `source_identifier` | 来源业务标识 |
| `license_name` | 项目登记许可 |
| `publisher` | 发布/分发机构 |
| `status` | 来源状态 |
| `created_at` | 登记时间 |

查询策略：`lineage_admin_only`。

### 3.2 `open_data_snapshot`

层级：lineage  
用途：记录不可变下载/选取快照。

关键字段：

- `snapshot_id`
- `source_id`
- `dataset_version`
- `source_hash`
- `snapshot_hash`
- `source_row_count`
- `snapshot_row_count`
- `period_start`
- `period_end`
- `local_path`
- `selection_method`
- `ingested_at`

关键关系：`source_id → open_data_source.source_id`。

### 3.3 `open_data_ingestion_run`

层级：lineage  
用途：记录幂等 raw→core 摄取运行。

关键字段：

- `run_id`
- `source_id`
- `snapshot_id`
- `transformation_version`
- `ingestion_time`
- `raw_row_count`
- `staging_row_count`
- `core_row_count`
- `status`
- `error_summary`

运行失败时不得发布活动数据集。

### 3.4 `open_data_quality_check`

层级：lineage  
用途：记录每次摄取运行的机器可验证质量门禁。

典型检查：

- 唯一性；
- 必填；
- 类型；
- 日期范围；
- 金额/电量业务范围；
- 外键与引用完整性；
- 重复；
- 时间顺序；
- 文件哈希；
- 行数；
- 数据集版本；
- 转换对账。

### 3.5 `raw_acn_session`

层级：raw  
用途：保留 ACN-Data 会话源记录。

关键业务字段：

- 源记录 ID；
- site/station/space；
- 源用户标识；
- connection/disconnect/done-charging 时间；
- `energy_kwh`；
- `payment_required`；
- `source_row_hash`；
- `run_id`。

敏感性：源用户标识按受限伪名数据处理。

### 3.6 `stg_acn_session`

层级：staging  
用途：标准化 ACN 会话。

核心映射：

| 源字段 | staging | core |
|---|---|---|
| `id` | `source_record_id` | `fact_charging_session.session_id` |
| `stationid` | `station_id` | `dim_station.station_id` |
| `connectiontime` | `connection_time` | `fact_charging_session.start_time` |
| `disconnecttime` | `disconnect_time` | `fact_charging_session.end_time/settlement_time` |
| `kwhdelivered` | `energy_kwh` | `fact_charging_session.energy_kwh` |
| `userinputs.paymentRequired` | `payment_required` | 服务费派生规则输入 |

## 5. 数据敏感性

典型等级：

- `internal_business`：内部业务字段；
- `restricted_pseudonymous`：伪名化用户/客户标识；
- `restricted_raw_payload`：无损原始载荷，仅治理/审计用途。

任何用户级敏感明细都不进入普通 ChatBI/RAG 结果。

## 6. Join 原则

1. 只允许语义层声明的等值 Join。
2. 不得自行猜测同名字段关系。
3. 不得跨 `charging_ops` 与 `sales_ops` 进行无治理 Join。
4. 事实表与事实表的跨表指标先聚合到共同粒度后再连接。
5. 未发布关系、未知表、未知字段全部 fail-closed。
