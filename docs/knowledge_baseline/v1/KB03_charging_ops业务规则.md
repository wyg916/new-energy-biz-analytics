# KB03｜charging_ops 业务规则

> 知识域：`business_rule`  
> 场景：`charging_ops`  
> 版本：`1.0.0`

## 1. 场景定位

`charging_ops` 用于新能源充电运营经营分析，核心对象包括：

- 充电会话；
- 场站；
- 设备；
- 用户；
- 电量；
- 收入；
- 能源成本；
- 经营毛利；
- 设备状态（仅在存在有效状态事实时）；
- 经营诊断。

DATA-4.1 活动公开源为 ACN-Data，通过项目登记的 ORNL OpenEnergyDataPortal 快照链路进入系统。

## 2. 当前活动数据范围

当前登记运行：

`DATA41-ACN-ORNL-26-V1`

当前公开源快照覆盖：

- 记录：26/26 条发现副本记录；
- 时间：2020-05-09 至 2020-06-09；
- 许可：以 DATA-4.1 来源登记为准；
- 源字段重点：连接、断开、完成充电、电量、站点/空间、用户输入。

RAG 回答具体数值时必须以当前 ACTIVE DatasetVersion、SemanticModelVersion 和数据库查询结果为准，不能把本文件中的范围描述当成实时数据。

## 3. 会话规则

### 3.1 完成会话

只有 `session_status='completed'` 的会话进入：

- 完成订单数；
- 充电量；
- 充电收入；
- 服务费收入；
- 用户指标；
- 相关经营派生指标。

### 3.2 时间

源时间先标准化后入库。查询层继续遵守平台版本的时间合同，所有窗口使用 `[start, end)`。

### 3.3 电量

`kwhdelivered → energy_kwh`，不进行比例缩放。

### 3.4 主键

源 ID、站点、产品/实体映射采用命名空间化稳定键，保证同一快照和转换版本可重复摄取。

## 4. 收入规则

ACN 源数据不直接提供完整经营结算金额。

当前项目将公开源电量与版本化费率规则组合，形成经营分析用派生字段：

- `electricity_fee_net_amount`
- `service_fee_net_amount`

其中 DATA-4.1 映射登记了 `paymentRequired` 对应的服务费派生规则。所有此类金额必须标记为派生结果并保留规则依据。

不得回答为“ACN 原站点实际账单收入”。

## 5. 能源成本规则

当前 `fact_energy_cost.purchase_price_per_kwh` 依据 DATA-4.1 登记的公开参考价格形成，核心规则为：

`energy_cost = settled_energy_kwh × purchase_price_per_kwh`

该价格是经营分析参考规则，不是特定场站采购合同价格。

## 6. 设备状态规则

当前 ACN 活动源没有提供足够的设备状态事件，因此：

- 不生成 `fact_device_status_event` 活动事实；
- `device_online_rate` 不得补造；
- `device_fault_rate` 不得补造；
- `station_utilization_rate` 在缺少可用枪口时长事实时返回数据不足。

系统可以解释“为什么不可计算”，不能为了页面完整返回默认比例。

## 7. 用户规则

用户标识只用于受控去重、分群和聚合：

- 不恢复真实身份；
- 不输出个人级结果；
- `active_user_count` 必须在目标范围重新去重；
- 权限过滤在查询和记忆召回前生效。

## 8. 经营分析优先级

常见分析顺序：

1. 看充电收入、充电量、完成订单数；
2. 看单均充电量、度电收入；
3. 对比环比/同比；
4. 下钻场站贡献；
5. 看能源成本及毛利变化；
6. 在存在状态事实时再看设备在线/故障和利用率；
7. 对异常变化做贡献拆解，而非直接宣称因果。

## 9. 不允许的结论

- 把公开源缺失的设备状态补成正常值；
- 把派生收入/成本描述为源站点原始财务数据；
- 把经营相关性直接描述为因果关系；
- 越过授权场站或区域查询；
- 将测试 fixture 混入当前活动数据集；
- 在缺少成本事实时给出完整毛利结论。
