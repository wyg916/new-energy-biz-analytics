# KB05｜收入、成本与毛利计算规则

> 知识域：`business_rule`  
> 场景：`charging_ops`、`sales_ops`  
> 版本：`1.0.0`

## 1. 总原则

1. 金额必须绑定场景、数据集版本、语义版本和运行标识。
2. `SOURCE`、`DERIVED`、`BUSINESS_ASSUMPTION` 三类字段必须区分。
3. 不同币种不得直接相加。
4. 缺少必要成本时，不能把缺失项默认为 0 后宣称完整毛利。
5. 退款、折扣、取消必须按场景规则进入净额计算。
6. 发布报告时应冻结当时的指标值、数据集版本、SQL/Query Plan 哈希和证据。

## 2. charging_ops

### 2.1 充电收入

`charging_revenue = Σ(electricity_fee_net_amount + service_fee_net_amount)`

仅统计完成会话。

### 2.2 服务费收入

`service_fee_revenue = Σ(service_fee_net_amount)`

当前活动公开源中服务费属于项目派生经营规则，不是 ACN 源字段。

### 2.3 电费成本

`energy_cost = Σ(settled_energy_kwh × purchase_price_per_kwh)`

当前采购价格是 DATA-4.1 登记的公开参考价格规则。

### 2.4 可变运营成本

`variable_operating_cost = Σ(amount where is_variable=true)`

仅当活动数据集中存在已发布有效费用事实时计算。没有有效事实时返回数据不足。

### 2.5 经营毛利

`gross_profit = charging_revenue - energy_cost - variable_operating_cost`

任何必要组成项不可用时，应返回“毛利口径数据不完整”，而不是静默把缺失项当 0。

### 2.6 毛利率

`gross_margin = gross_profit / charging_revenue`

当 `charging_revenue=0` 时返回数据不足。

### 2.7 度电收入

`revenue_per_kwh = charging_revenue / charging_volume_kwh`

### 2.8 度电成本

`cost_per_kwh = (energy_cost + variable_operating_cost) / charging_volume_kwh`

只有成本组成项完整时才给出完整度电成本。

## 3. sales_ops

### 3.1 毛额

订单行基础：

`gross_amount = quantity × unit_price`

### 3.2 净收入

`net_revenue` 为折扣和退款处理后的经营收入。具体退款/取消归属以活动语义模型的订单状态合同为准。

### 3.3 成本

UCI 源没有成本字段。DATA-4.1 当前规则：

`cost_amount = 非退款净收入 × 70%`

该规则必须被描述为当前场景的成本假设，不得描述为源数据观测成本。

### 3.4 毛利

`gross_profit = net_revenue - cost_amount`

### 3.5 毛利率

`gross_margin = gross_profit / net_revenue`

当净收入为 0 时返回数据不足。

## 4. 跨场景金额

当前：

- charging_ops 的派生费率依据与销售源的 UnitPrice 不属于同一币种治理链；
- UCI UnitPrice 当前未进行币种转换。

因此禁止：

`charging_ops revenue + sales_ops revenue`

直接形成“集团总收入”。

若未来需要跨场景金额汇总，必须新增：

- `currency_code`
- `fx_rate`
- `fx_rate_source`
- `fx_rate_version`
- `conversion_timestamp`

并将换算规则纳入语义版本和审计。

## 5. 对账要求

金额类指标至少进行：

1. 明细到订单/会话汇总；
2. 订单/会话到日汇总；
3. 日汇总到查询周期；
4. API 结果与数据库结果；
5. 报告/页面与 API；
6. 数据集版本与运行 ID 核对。

差异必须有明确原因，禁止在前端通过格式化或 fallback 隐藏。
