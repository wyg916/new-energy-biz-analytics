# KB06｜公开数据接入、质量与发布说明

> 知识域：`scenario_guide`  
> 场景：`charging_ops`、`sales_ops`  
> 版本：`1.0.0`

## 1. 标准链路

业务数据统一走：

`Source → Snapshot → Raw → Staging → Core → Quality → Dataset Version → Semantic Activation → API → UI`

禁止：

- 前端直接读取本地 CSV/Excel；
- 前端硬编码业务数值；
- API 失败后生成替代经营数据；
- 跳过数据库直接将下载文件结果展示为正式指标。

## 2. 当前活动公开源

### charging_ops

- 来源：ACN-Data，经项目登记的 ORNL OpenEnergyDataPortal 快照链路；
- 运行：`DATA41-ACN-ORNL-26-V1`；
- 当前快照：26 条；
- 时间：2020-05-09 至 2020-06-09。

### sales_ops

- 来源：UCI Online Retail；
- 运行：`DATA41-UCI-ONLINE-RETAIL-352-V1`；
- 源总行数：541,909；
- 当前确定性样本：27,095；
- 时间：2010-12-01 至 2011-12-09；
- 保留 `source_row_number` 和 SHA-256 证据。

## 3. 来源登记

每个来源至少登记：

- `source_id`
- 来源名称
- 发布/分发机构
- 来源标识
- 许可
- 状态
- 来源地址
- 登记时间

没有完成来源登记的数据不能成为 ACTIVE Dataset。

## 4. 不可变快照

每个快照至少保存：

- `snapshot_id`
- `dataset_version`
- `source_hash`
- `snapshot_hash`
- 源行数
- 快照行数
- 时间范围
- 选择方法
- 本地受控路径
- 摄取时间

快照发生变化时创建新版本，不覆盖旧证据。

## 5. 摄取运行

`open_data_ingestion_run` 至少记录：

- `run_id`
- `source_id`
- `snapshot_id`
- `transformation_version`
- `ingestion_time`
- raw/staging/core 行数
- `status`
- `error_summary`

摄取必须幂等。同一快照和转换版本重复运行，不应静默产生重复事实。

## 6. Raw 层

原则：

- 尽可能保留源字段；
- 保存行哈希；
- 保留源行号或源记录标识；
- 敏感原始载荷只允许治理/审计访问；
- 不直接供普通业务查询。

## 7. Staging 层

负责：

- 字段名标准化；
- 类型转换；
- 时间标准化；
- 稳定主键；
- 取消/退款标记；
- 空值处理；
- 单位规范；
- 来源字段与派生字段分离。

转换规则必须版本化。

## 8. Core 层

Core 是业务查询事实层。

必须：

- 主键稳定；
- 外键可验证；
- 场景隔离；
- 经营字段口径明确；
- 来源/派生边界可追溯；
- 只从质量通过的运行发布。

## 9. 质量门禁

DATA-4.1 当前执行 28 项质量检查，覆盖：

- 唯一性；
- 必填；
- 类型；
- 日期范围；
- 金额/电量合理范围；
- 引用完整性；
- 重复；
- 时间顺序；
- 异常值观察；
- 文件哈希；
- 行数；
- 数据版本；
- 转换对账。

任一强制检查失败：

`ingestion_run = FAILED`

并阻止活动发布。

## 10. 当前字段真实性边界

### ACN

源字段：

- 连接/断开/完成充电时间；
- 电量；
- 场站/空间；
- 用户输入。

派生：

- 服务费经营金额；
- 能源成本参考金额；
- 部分场站建模属性。

源没有提供：

- 完整设备状态；
- 站点实际财务结算价。

### UCI

源字段：

- 发票号；
- 商品编号；
- 商品描述；
- 数量；
- 发票时间；
- UnitPrice；
- CustomerID；
- Country。

派生/假设：

- 成本金额；
- 销售人员占位；
- 缺失 CustomerID 的发票内伪名键。

## 11. 当前未激活候选

- NREL AFDC：保留候选目录，当前验收环境未形成稳定活动摄取链路；
- PJM Data Miner 2：当前不作为提交快照的活动数据源。

RAG 回答必须区分“候选来源”和“当前 ACTIVE 来源”。

## 12. 故障处理

出现以下情况必须 fail-closed：

- 来源下载/读取失败；
- SHA 不匹配；
- 行数异常；
- 转换失败；
- 质量门禁失败；
- DatasetVersion 未发布；
- SemanticModelVersion 未激活；
- 权限映射缺失。

系统应返回明确状态，不用前端数值填充。
