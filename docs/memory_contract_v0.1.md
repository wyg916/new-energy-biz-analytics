# P0 记忆与运行证据合同 v0.1

> 状态：Phase 0.1 开发输入基线
> P0 目标：同一会话内可控连续追问与完整 `analysis_run` 证据链
> P1 后移：用户长期偏好、历史案例检索、纠错记忆、记忆管理页和自动行为学习。

## 1. 权威与冲突优先级

```text
本轮用户明确指令
> 当前已验证 Query Plan
> 已批准组织规则
> 最新成功业务数据与已发布指标版本
> 当前会话结构化状态
> P1 用户长期偏好
> P1 已确认历史案例
> 模型临时推断
```

当前业务事实只来自质量通过的数据批次和已发布指标版本。记忆不得作为当前收入、成本、设备状态等业务数字的事实源。

## 2. P0/P1 边界

| 能力 | P0 | P1 |
|---|---:|---:|
| 当前任务工作状态 | 是 | 延续 |
| 同一会话结构化上下文 | 是 | 延续 |
| 指标、时间、区域、城市、站点、比较方式和分析对象继承 | 是 | 延续 |
| 本轮明确条件覆盖旧条件 | 是 | 延续 |
| 新会话临时状态隔离 | 是 | 延续 |
| `analysis_run` 完整证据链 | 是 | 延续 |
| 用户明确长期偏好 | 否 | 是 |
| 历史分析案例检索/重放 | 否 | 是 |
| 纠错记忆和 candidate 确认 | 否 | 是 |
| 记忆管理页面 | 否 | 是 |
| 自动行为学习 | 否 | 后续评审 |
| 跨团队/多 Agent 共享记忆 | 否 | 不在当前计划 |

P0 不得创建伪长期记忆接口或用聊天历史全文代替结构化状态。

## 3. 工作记忆

工作记忆保存一次分析任务尚未完成的临时运行状态，建议存储在 Redis 或等价临时存储中。

必需字段：

| 字段 | 说明 |
|---|---|
| task_id | 当前分析任务 ID |
| request_id / run_id | 关联请求与运行 |
| user_id / conversation_id | 身份与会话边界 |
| current_stage | `planning` / `guarding` / `executing` / `analyzing` / `answering` |
| query_plan_digest | 计划摘要，不保存未脱敏原始敏感输入 |
| partial_result_refs | 结构化中间结果引用 |
| started_at / last_activity_at | 生命周期 |
| expires_at | 空闲 2 小时过期 |
| state_version | 乐观并发版本 |

空闲 2 小时后物理清理；任务完成、取消或失败后可立即释放大结果，仅保留 `analysis_run` 证据摘要。

## 4. `session_state`

粒度：一个用户的一次会话。主键：`conversation_id`。

| 字段 | 类型建议 | 必填 | 说明 |
|---|---|---:|---|
| conversation_id | UUID | 是 | 会话唯一标识 |
| user_id | UUID | 是 | 所属用户 |
| role_ids | JSONB | 是 | 状态写入时的角色快照，仅供审计，读取时重新鉴权 |
| active_intent | VARCHAR(64) | 否 | 当前意图 |
| active_metrics | JSONB | 否 | 指标 ID 与版本 |
| active_dimensions | JSONB | 否 | 当前维度 |
| active_filters | JSONB | 否 | 区域/城市/站点等稳定 ID |
| active_time_range | JSONB | 否 | 起止、粒度、时区和原始表达 |
| active_comparison | JSONB | 否 | 环比/同比/自定义比较 |
| active_entities | JSONB | 否 | 当前分析对象与指代 |
| current_step | VARCHAR(64) | 否 | 当前分析步骤 |
| source_run_ids | JSONB | 是 | 状态所依据的运行 |
| state_version | INTEGER | 是 | 从 1 递增，防并发覆盖 |
| created_at / updated_at | TIMESTAMPTZ | 是 | 审计时间 |
| expires_at | TIMESTAMPTZ | 是 | 最长 7 天，不能因被动读取无限续期 |
| status | VARCHAR(16) | 是 | `active` / `expired` / `cleared` |

规则：

- 只保存结构化字段和必要实体 ID，不默认保存完整聊天正文；
- 每轮成功解析后以 compare-and-swap 更新 `state_version`；
- 当前明确条件覆盖旧条件，并记录 `inherited_fields` 与 `overridden_fields`；
- 过期、清空、权限变化或来源运行不可用时不得继承；
- 新会话创建独立状态，不从旧会话复制临时值；
- 区域/站点权限每轮重新校验，旧状态不能扩大权限；
- 状态最长保留 7 天，用户结束会话或主动清空时立即停止使用。

## 5. `analysis_run`

`analysis_run` 是运行证据，不是可直接召回的长期记忆。

必需证据：

- 身份、角色、授权范围摘要和策略版本；
- 问题摘要、会话 ID 和状态版本；
- Query Plan、合同版本、继承/覆盖字段；
- 指标、维度、Join 和数据批次版本；
- SQL hash、脱敏参数、Guard 决定和 EXPLAIN 摘要；
- 结构化结果摘要、行数和结果 digest；
- Answer Guard 输入/输出 digest、模型版本和降级状态；
- 运行阶段、耗时、错误码、重试和最终状态；
- `source_type=simulated`、数据期和 `run_id`；
- 用户反馈（若 P0 仅作运行反馈，不升级为长期事实）。

Alpha 的 `analysis_run` 保留 180 天。过期清理前必须保留最小审计和已导出报告所需的可复现引用；报告若引用即将过期的运行，应提前固化获批的证据包，而不是静默延长全部原始结果。

## 6. TTL、删除与审计

| 对象 | 保留策略 | 删除/过期行为 | 最小审计 |
|---|---|---|---|
| 工作记忆 | 空闲 2 小时 | 立即停止使用并物理清理临时缓存 | task_id、清理时间、原因 |
| 会话状态 | 最长 7 天 | 状态设为 expired/cleared，不再继承；敏感正文不存在或被清除 | conversation_id、用户、动作、时间 |
| 未确认 candidate | P1，30 天 | 到期不召回，按策略清理 | candidate_id、状态、时间 |
| 用户明确偏好 | P1，至用户删除/停用 | 删除/停用后立即停止召回 | memory_id、动作、时间 |
| 历史分析记录 | Alpha 180 天 | 到期归档或删除，不再作为事实 | run_id、保留动作、时间 |
| 删除/使用审计 | 180 天 | 到期按审计策略清理 | 最小元数据，不保留被删正文 |

删除必须是幂等操作。收到删除后，缓存、索引和检索层立即失效；审计只保留证明动作发生所需的最小字段，不保留被删除内容。

## 7. 权限与隐私

- 会话状态只能由所属用户及当前请求链读取；系统管理员默认不能读取会话正文；
- 任何状态或运行证据读取前重新执行当前 RBAC；
- 不保存密码、Token、密钥、连接串、完整 SQL 结果集、用户敏感信息或无权限实体摘要；
- 权限拒绝不得泄露其他区域/用户状态或运行是否存在；
- 审计可以记录被过滤的 `memory_id`/`run_id` 哈希，但不能记录被拒绝内容；
- 导出只携带本次任务相关、已授权且可追溯的运行证据。

## 8. 多轮解析示例

第一轮：“2026 年 6 月区域 A 充电收入环比如何？”

```json
{
  "metrics": ["charging_revenue"],
  "filters": {"region": "region_a"},
  "time_range": ["2026-06-01T00:00:00+08:00", "2026-07-01T00:00:00+08:00"],
  "comparison": "mom",
  "dimensions": [],
  "state_version": 1
}
```

第二轮：“哪些场站拖累最大？”继承指标、时间、区域和比较方式，新增 `station` 维度和负贡献排序，`state_version=2`。

第三轮：“改看区域 B。”只覆盖区域过滤，保留指标、时间和比较方式，记录 `overridden_fields=[region]`，`state_version=3`。

新建会话后询问“哪些场站拖累最大？”不得继承上述状态，应要求补充指标、时间和范围。

## 9. MT-01—MT-12 测试映射

| 测试 | 场景 | P0/P1 | 预期 |
|---|---|---|---|
| MT-01 | 华东收入后追问“哪些站点影响最大” | P0 | 继承指标/时间/区域，增加站点维度 |
| MT-02 | 本轮说“改看华南” | P0 | 明确新区域覆盖旧区域，记录覆盖 |
| MT-03 | 新会话问“收入情况” | P0 | 不继承旧会话临时状态，必要时澄清 |
| MT-04 | 设置默认按周/关注毛利率 | P1 | P0 明确返回未支持，不创建偏好 |
| MT-05 | 查询历史类似案例 | P1 | P0 明确返回未支持，不检索历史 |
| MT-06 | 历史称离线、当前已恢复 | P1 完整；P0 运行证据边界 | 当前数据库事实优先；P0 不自动召回历史结论 |
| MT-07 | 召回其他租户/区域状态 | P0 | 403，不泄露存在性，记录安全审计 |
| MT-08 | 删除个人长期偏好 | P1 | P0 无长期偏好；P1 删除后立即停止召回 |
| MT-09 | 模型生成未经确认结论 | P0 | 只存在于当前回答/运行，不能成为长期事实 |
| MT-10 | 过期会话状态 | P0 | 排除并记录 `filtered_expired` |
| MT-11 | 大量上下文 | P0 | 只注入完成当前任务所需结构化字段，不注入全文 |
| MT-12 | 用户指出数据延迟 | P1 纠错；P0 运行反馈 | P0 保存反馈到当前 `analysis_run`，不升级为长期事实 |

P0 阶段必须实现并通过 MT-01、02、03、07、09、10、11；MT-06 和 MT-12 验证 P0 的事实优先与不自动沉淀边界；MT-04、05、08 的完整能力属于 P1。

## 10. fail-closed

身份、权限、会话版本、状态解析、来源运行或审计不可用时，不继承状态。系统可以把本轮当作无上下文请求并澄清，但不得猜测、跨会话读取或绕过权限继续执行。
