# 阶段实施计划（Phase 0—8，Phase 0.1 更新）

> 状态：DEC-01—DEC-10 已批准，Phase 0.1 开发输入已补齐；**不构成任何编码阶段的自动授权**
> 启动规则：每个阶段必须先提交实施卡，经批准后再修改；阶段验收通过后才可进入下一阶段。

## 1. 通用阶段门

每个阶段实施卡必须包含：目标、输入、交付物、前置依赖、修改范围、非目标、迁移、依赖、数据库影响、安全影响、测试、验收证据、已知限制、回滚方式和并行策略。

通用门禁：

- 不得把设计、占位或 mock 描述为已实现；
- 不得使用真实密钥或未经授权的数据；
- 数据库迁移必须可回滚；
- 测试写入隔离数据库或临时目录；
- 任何范围、指标、权限或数据假设发生重大变化时退回 DoR 复审；
- 每个工作包独立提交和验收；
- 不得通过删除或跳过失败测试让阶段变绿。

## Phase 0：开发准备度检查与基线建立

**目标**

核验资料、范围、DEC-01—DEC-10、架构、DoR 和缺失输入，形成可评审的项目准备基线。

**输入**

- v1.1 立项设计文档；
- 当前仓库事实；
- 项目负责人对范围、数据、指标、记忆和时间的决定。

**交付物**

- `docs/implementation_readiness_report.md`；
- `docs/project_scope_baseline.md`；
- `docs/architecture_baseline.md`；
- `docs/decision_log.md`；
- `docs/phase_plan.md`；
- `docs/missing_inputs.md`。

**验收标准**

- 所有结论有文档章节或仓库证据；
- 不创建业务代码或占位功能；
- 明确 DoR、允许阶段、待确认问题和禁止阶段；
- 项目负责人完成决策确认并指定缺失输入责任人。

**回滚方式**

删除或回退本轮新增准备文档；不涉及代码、数据库或外部系统。本轮未授权删除，因此如需回滚必须由项目负责人另行批准。

**并行**

不建议并行修改基线文档；由一个事实源统一收敛，评审人可并行提供意见。

## Phase 0.1：决策冻结、输入补齐和 DoR 复审

**已完成：** DEC-01—DEC-10 冻结；根级治理文件；数据、指标、Query Plan、安全和记忆合同；40 道固定评测；低保真静态原型；事实基线和 DoR 复审。

## Phase 1：工程骨架、配置、认证、迁移和测试基线

**目标**

建立可启动、可测试、默认安全、可迁移和可追溯的最小工程骨架，不实现指标、驾驶舱、ChatBI、记忆、异常归因或报告业务功能。

**前置输入**

- DoR 复审达到启动门；
- DEC-01—DEC-10 已批准；
- 技术版本、端口、配置、身份与权限最小模型获批；
- Phase 1 实施卡获批。

**交付物**

- 独立 Git 仓库、根级 `AGENTS.md`、README、`.gitignore`、`.env.example`；
- 前后端最小启动骨架和健康检查；
- 集中配置、密钥注入和 fail-closed；
- 用户/角色/组织范围的最小认证框架；
- Alembic 基线和空迁移验证；
- pytest、前端单测、Playwright/契约测试骨架；
- Docker Compose 基线和本地开发命令。

**修改范围**

工程配置、应用入口、健康检查、认证框架、迁移基础、测试工具和文档。

**测试要求**

- 配置缺失拒绝启动；
- 健康检查和依赖状态正确；
- 401/403 最小负向测试；
- 迁移 upgrade/downgrade；
- 隔离测试数据库验证；
- Compose 启停和全新环境冒烟。

**验收标准**

- 新环境只按 README 可启动；
- 无真实密钥和隐式 C 盘/本机路径依赖；
- 迁移可回滚；
- 测试命令稳定重复；
- 未出现业务占位功能被标记完成。

**回滚方式**

回退 Phase 1 独立提交；执行迁移 downgrade；删除本阶段创建的无状态容器/测试卷（需在实施卡中列出精确目标）。

**并行**

有限允许：前端骨架、后端骨架、测试配置和文档可在目录/端口/API 健康契约冻结后并行。认证、配置和迁移基线必须串行收敛。

## Phase 2：数据模型、模拟数据、质量规则和指标语义层

**目标**

建立唯一字段级数据模型、可复现模拟数据、质量门禁和 15 项 P0 指标语义层。

**前置输入**

- Phase 1 通过；
- DEC-02、DEC-04 获批；
- 字段级模型、指标字典和数据生成规则获批。

**交付物**

- 业务事实/维表、元数据、`analysis_run` 的迁移；
- 模拟数据生成器、固定种子和数据来源标签；
- 唯一性、完整性、范围、关系、逻辑、时效和波动规则；
- 指标注册表、版本和发布状态；
- 15 项指标公式与基准 SQL 测试。

**测试要求**

迁移、生成器确定性、关系完整性、金额/时间精度、零分母、空值、同比环比边界、质量阻断和回滚测试。

**验收标准**

- 相同种子生成一致数据；
- 业务关系和汇总守恒；
- P0 指标与基准 SQL 一致；
- 只有已发布指标可被查询；
- 数据质量失败不发布 ADS/最近成功版本。

**回滚方式**

回退迁移和数据版本；测试/模拟数据可按批次清理并重建；不修改外部或真实数据源。

**并行**

字段模型冻结后，生成器、质量测试和指标公式测试可并行；迁移与模型定义由单一所有者串行维护。

## Phase 3：经营驾驶舱和专题分析

**目标**

在已验证指标服务上交付经营总览、趋势、区域/站点排名，以及收入、毛利、场站专题分析。

**前置输入**

Phase 2 通过；页面原型、结果契约和权限范围冻结。

**交付物**

- 驾驶舱 API 与页面；
- 时间、区域、站点筛选；
- 数据状态、来源标签、质量和 `run_id`；
- 收入、毛利、场站专题页面；
- 空态、错误态、延迟态和无权限状态。

**测试要求**

指标一致性、筛选联动、时间边界、权限、降级状态、可访问性、API 契约和 E2E。

**验收标准**

页面数字与 Phase 2 指标服务一致；切换范围不泄漏数据；失败不伪装成功；关键任务在原型规定步骤内完成。

**回滚方式**

回退 API/UI 提交和只读查询视图；不得回退已发布数据事实或审计记录。

**并行**

API、前端和 E2E 可基于冻结契约并行；指标公式和结果契约不得在本阶段并行改动。

## Phase 4：Query Plan、SQL Compiler 和 Query Guard

**目标**

建立核心可信问数执行链，不实现最终自然语言回答包装。

**前置输入**

Phase 2 通过；DEC-05 获批；Query Plan Schema、语义关系、权限和 SQL 安全策略冻结。

**交付物**

- Query Plan 版本化 Schema、验证器和澄清契约；
- 确定性参数化 SQL Compiler；
- AST/表字段函数白名单、单条只读、LIMIT、timeout 和成本控制；
- 查询审计和错误码；
- 正/负查询样例集。

**测试要求**

Schema 契约、确定性编译、时间/Join/聚合、注入、DDL/DML、多语句、注释绕过、越权、高成本、超量和错误脱敏测试。

**验收标准**

危险和越权请求拒绝率 100%；同一计划产生一致 SQL/hash；所有执行可关联审计；Planner 无数据库执行权限。

**回滚方式**

回退编译/安全规则版本；禁用新版本并恢复最近已验证策略；审计记录保留。

**并行**

Schema 金标、Compiler 和 Guard 负向语料可并行；Schema、权限或语义关系变更必须串行批准。

## Phase 5：ChatBI 结果、证据面板和固定评测

**目标**

在 Phase 4 安全链路上交付 P0 自然语言问数、结构化结果、图表、解释和证据面板。

**前置输入**

Phase 3/4 通过；固定评测集、回答结构、数字约束和模型降级契约冻结。

**交付物**

- 问题理解、歧义澄清和有限意图；
- KPI/趋势/排名/比较/贡献结果呈现；
- Answer Guard 和数字绑定；
- Query Plan、SQL、指标口径、来源、时间和 `run_id` 证据面板；
- 30—50 题固定评测与报告；
- 模型不可用降级。

**测试要求**

计划、SQL、结果、回答、图表、安全、数据不足、模型失败、无依据数字和重复运行稳定性。

**验收标准**

达到获批准确率；无依据数字率 0；核心结果证据完整率 100%；模型失败仍可显示结构化结果。

**回滚方式**

回退提示/规则/模型配置版本，保留结构化查询能力；评测报告和失败样例不可删除。

**并行**

前端结果/证据面板、Answer Guard 和评测工具可在结果契约冻结后并行。

## Phase 6：结构化会话状态、analysis_run 和记忆能力

**目标**

实现获批的 P0 会话连续性和运行证据；只有 DEC-08 批准为 P1 的能力得到单独授权时，才扩展长期记忆。

**前置输入**

Phase 5 通过；DEC-08—10 获批；权限、TTL、删除和审计契约冻结。

**交付物（P0）**

- `session_state`：指标、维度、时间、筛选、实体、步骤和版本；
- 当前会话有限继承、显式覆盖和新会话隔离；
- `analysis_run` 全链路证据与重放边界；
- 记忆使用/过滤审计的最小结构。

**P1 扩展（需另行批准）**

用户明确偏好、历史案例检索、确认/纠错、记忆管理、过期和删除。

**测试要求**

多轮继承、条件覆盖、指代、新会话隔离、并发版本、TTL、事实冲突、越权不泄露、删除后不召回和上下文预算。

**验收标准**

当前指令和数据库事实优先；无跨租户/跨区域召回；未确认模型结论不能升级为事实；所有采用/过滤有审计。

**回滚方式**

停用新记忆策略和召回版本；清理临时会话缓存；持久审计和必要历史版本保留。

**并行**

权限过滤、会话状态和审计不可由不同线程同时改变契约。UI 管理页只能在服务契约冻结后并行。

## Phase 7：异常规则、收入/毛利拆解和贡献归因

**目标**

交付可解释、可复现、不夸大因果的异常和经营变化诊断。

**前置输入**

Phase 2/3 通过；异常算法规格、基准期、阈值、残差和小样本规则冻结。

**交付物**

- 阈值、同比/环比、移动基线和同群异常；
- 收入量价与毛利成本拆解；
- 区域/站点/设备贡献定位；
- 异常等级、限制、关联因素和证据；
- 至少 3 个金标业务案例。

**测试要求**

离线基准、贡献守恒、残差、零值/负值/退款、小样本、数据质量、相关非因果文案和权限测试。

**验收标准**

贡献合计在获批容差内；残差超阈值明确提示；设备等因素只表述关联/疑似影响；案例可完整复现。

**回滚方式**

按规则/算法版本回退；历史异常和确认记录保留版本，不覆盖原证据。

**并行**

收入与毛利算法可在共同口径冻结后并行；异常等级、贡献接口和前端契约由单一基线控制。

## Phase 8：报告草稿、审计、Docker 和最终验收

**目标**

完成报告草稿、全链路审计、部署加固、回归和 Alpha 验收，不扩张为 Agent 自动执行。

**前置输入**

Phase 1—7 均通过；DEC-06/07 获批；Alpha 验收矩阵和证据格式冻结。

**交付物**

- 周报/月报草稿、版本、来源运行和人工确认；
- DOCX/PDF/HTML 中获批范围的导出；
- 全链路审计、错误与可观测性；
- 生产相似 Compose、迁移、备份/恢复说明；
- README、限制声明、测试/评测报告和案例证据；
- 全新环境安装和最终验收记录。

**测试要求**

全量单元、契约、集成、E2E、安全、质量、AI 评测、记忆专项、导出一致性、安装、升级、回滚和故障演练。

**验收标准**

Alpha Definition of Done 全部满足；P0 回归 100% 通过；危险查询拒绝 100%；无依据数字 0；全新环境可复现；项目负责人签署。

**回滚方式**

按发布版本回退应用和迁移；报告与审计保留历史版本；禁止删除失败证据来制造通过结论。

**并行**

文档、安装验证和独立验收可并行；发布包、迁移和最终证据由单一发布负责人收敛。

## 2. T0+30 目标里程碑

T0 定义为 DoR 达到启动门且项目负责人正式授权 Phase 1 的日期。

| 目标门 | 目标日期 | 说明 |
|---|---|---|
| Phase 1 完成 | T0+3 | 工程、配置、认证、迁移和测试基线 |
| Phase 2 完成 | T0+8 | 数据、模拟生成、质量和 15 项指标 |

| Phase 4 完成 | T0+17 | Query Plan、Compiler、Guard |
| Phase 5 完成 | T0+21 | ChatBI 结果、证据和固定评测 |
| Phase 6 完成 | T0+24 | 会话状态和 `analysis_run` |

里程碑是目标而非降低质量门的理由。任何范围、资源或关键假设变化必须重估并记录。
