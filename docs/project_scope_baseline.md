# 产品范围基线 v1.0（已批准）

> 批准日期：2026-07-22
> 批准人：项目负责人王迎港
> 状态：**DEC-01—DEC-10 已冻结，可作为 Phase 1 实施卡输入**
> 来源：v1.1 第 1、3—9、15、17、19 章及 Phase 0.1 项目负责人确认

## 1. 产品定位

本项目是面向新能源充电运营企业的 AI 增强经营分析平台。它以统一指标语义层为基础，提供经营驾驶舱、受控智能问数、异常诊断、贡献度归因和报告草稿能力，目标是把“人工取数—制作报表—解释原因”升级为可追溯、可评测、可复用的分析闭环。

它不是通用聊天机器人、任意数据库自然语言转 SQL 工具、自动交易/控制系统或多 Agent 自动执行平台。

## 2. 目标用户与优先顺序

### 2.1 P0 核心用户

1. 经营负责人：查看总体经营、目标差异和重点风险；
2. 区域运营经理：定位区域/场站的收入、毛利和设备问题；
3. 数据分析师/系统管理员：数据分析师维护口径、验证查询和查看证据；系统管理员维护用户、角色、组织范围和已审批配置。两类权限在系统内分离。

### 2.2 次级用户

- 场站运营人员；
- 经营/财务分析人员。

上述次级用户明确进入 P1，不作为 Alpha P0 的独立角色验收对象。

## 3. P0：产品级可信 Alpha

P0 建议冻结为以下最小闭环：

1. 经营驾驶舱：经营总览、趋势、区域/站点排名、异常摘要、数据状态；
2. 固定 15 项已发布核心指标及统一语义层；
3. 收入、毛利、场站三个专题分析；
4. 结构化 Query Plan、版本化契约和澄清机制；
5. 确定性参数化 SQL Compiler；
6. Query Guard：只读、AST 白名单、权限、资源限制和审计；
7. 规则异常、同比/环比/同群对比、贡献拆解和残差说明；
8. 报告草稿生成，所有数字绑定结构化结果和 `analysis_run`；
9. 登录、角色、组织/区域数据范围和审计；
10. 当前会话内的结构化状态、有限追问、显式条件覆盖和 `analysis_run` 证据链；
11. Docker Compose、Alembic、配置 fail-closed、日志和健康检查；
12. 固定问题集、单元/契约/集成/E2E/安全/数据质量/AI 评测；
13. 所有页面和导出显示数据来源、数据时间、指标版本和运行标识。

### 3.1 已冻结的 P0 15 项指标

唯一执行口径见 `docs/metric_dictionary_v0.1.md`：

1. `charging_revenue`（充电收入）；
2. `service_fee_revenue`（服务费收入）；
3. `completed_order_count`（完成订单数）；
4. `charging_volume_kwh`（充电量）；
5. `energy_cost`（电费成本）；
6. `variable_operating_cost`（可变运营成本）；
7. `gross_profit`（经营毛利）；
8. `gross_margin`（毛利率）；
9. `avg_order_energy_kwh`（单均充电量）；
10. `revenue_per_kwh`（度电收入）；
11. `cost_per_kwh`（度电成本）；
12. `station_utilization_rate`（场站利用率）；
13. `device_online_rate`（设备在线率）；
14. `device_fault_rate`（设备故障率）；
15. `active_user_count`（活跃用户数）。

用户复购率、站均日收入、枪均日充电量和作为独立指标的异常影响金额进入 P1 或后续评审。

## 4. P1：Beta 增强范围

- 指标扩展到 30 项以上并增加发布流程和目标值；
- 可配置数据导入与增量刷新；
- 更丰富筛选、收藏、导出与移动适配；
- 有限自由查询、推荐问题和完整会话管理；
- 异常规则配置、人工确认和反馈闭环；
- 用户明确偏好、授权历史案例检索、记忆管理和使用审计；
- 报告定时生成、审批和模板管理；
- 更细组织权限、导出控制、监控告警、备份恢复和性能基线。

## 5. P2：V1 及后续

- 企业数据源连接、CDC 和更成熟的数据隔离；
- 指标审批、血缘、影响分析和多口径适配；
- 自定义看板、订阅和组织模板；
- 多数据集、复杂语义、个性化和成本治理；
- 预测性异常与任务/工单联动；
- 跨系统发送与 Agent 自动执行；
- 生产级多租户、SSO、细粒度行列权限；
- 高可用、灰度发布和容量规划。

P2 项目必须经过单独立项，不能因为架构中预留接口而被描述为已实现。

## 6. 明确排除项

Alpha 不包含：

- LLM 自由生成并执行任意 SQL；
- 多 Agent 自治协作；
- 自动邮件、企业微信、工单闭环和跨系统执行；
- 自动学习用户全部行为；
- 未审批的组织级自动记忆；
- 跨租户共享记忆；
- 自动交易、储能调度或生产控制；
- 生产级多租户、高可用集群和商业 SLA；
- 任意数据源、任意字段和任意复杂查询；
- 与核心业务无关的复杂动画、3D 大屏或移动 App；
- 未经授权的真实企业生产数据。

## 7. 与相关项目的边界

### 7.1 电力智能运营分析项目

- 对方领域：电力市场价格、负荷、天气和预测运行；
- 本项目领域：企业经营、场站、设备、用户、收入和成本；
- 允许复用：无业务含义的 UI 组件、日志/配置/认证基础库，或通过明确版本接口读取预测结果；
- 禁止混用：业务数据库、迁移、指标字典、测试数据、审计记录、运行证据和项目对外叙事。

### 7.2 运营 Agent 项目

- 本项目只生成分析结果和可审核报告草稿；
- 自动通知、工单流转、跨系统动作和状态推进属于运营 Agent 项目；
- 本项目不得在 P0 中创建虚假的 Agent 占位能力。

### 7.3 数据与作品叙事独立性

本项目应独立初始化 Git、文档、数据域、迁移链和发布证据。复用组件必须记录来源、版本、修改范围和许可证/归属，不得让复用掩盖项目自身尚未实现的能力。

## 8. P0 三个完整业务场景

### 8.1 场景 A：经营驾驶舱监控

- 用户：经营负责人、区域运营经理；
- 输入：时间范围、授权区域、可选城市/场站和比较方式；
- 系统步骤：鉴权 → 读取质量通过批次 → 计算已发布指标 → 展示当前值、比较、趋势、排名和异常摘要；
- 输出：指标卡、趋势、区域/场站排名、数据状态、来源、数据时间和 `run_id`；
- 失败状态：空数据、刷新失败、数据延迟、无权限和指标不可用；
- 验收：页面数字与指标基准 SQL 一致，筛选联动不扩大权限，失败不覆盖最近成功结果。

### 8.2 场景 B：收入下降诊断与连续追问

- 用户：区域运营经理、数据分析师；
- 输入：当前期、比较期、授权区域和 `charging_revenue`；
- 系统步骤：生成/验证 Query Plan → Guard → 计算收入变化 → 拆解订单数、单均电量、度电收入和残差 → 定位负贡献场站；
- 输出：总变化、因素贡献、场站贡献、相关设备信号、限制、Query Plan、SQL hash 和 `run_id`；
- 多轮：追问“哪些场站影响最大”继承指标/时间/区域/比较方式；“改看区域 B”覆盖区域；
- 失败状态：时间或比较不明确先澄清，数据质量失败拒绝诊断，无权限不泄露对象；
- 验收：显式贡献加残差等于总变化；回答数字全部来自结构化结果；设备仅表述相关或疑似影响。

### 8.3 场景 C：毛利下降诊断与报告草稿

- 用户：经营负责人、数据分析师；
- 输入：当前期、比较期、授权范围和 `gross_profit`；
- 系统步骤：分别聚合收入、电费成本、可变运营成本 → 计算毛利变化 → 拆解贡献 → 形成可审核报告草稿；
- 输出：毛利/毛利率、收入与成本贡献、重点场站、残差、来源运行和报告草稿；
- 失败状态：任一成本源缺失时不生成完整归因；模型不可用时保留结构化结果、报告解释降级；
- 验收：毛利公式守恒，成本上升对毛利贡献方向正确，报告数字与源 `analysis_run` 完全一致，不能自动发送或创建工单。

## 9. Alpha Definition of Done

Alpha 完成必须同时满足：

1. 范围、指标、数据、接口、权限和安全契约均有获批版本；
2. 全新环境可按 README 启动数据库、后端、前端和任务组件；
3. 迁移可升级和回滚，不依赖未声明的本机状态；
4. 模拟/替代数据有生成规则、来源标签、固定种子和质量报告；
5. P0 指标公式、时间边界、空值、零分母和基准 SQL 全部通过测试；
6. 核心查询严格经过 `Query Plan -> SQL Compiler -> Query Guard -> 执行`；
7. 危险、越权和高成本查询拒绝率为 100%；
8. 回答中的业务数字 100% 来自结构化结果；
9. 核心结果具备来源、数据时间、指标版本、Query Plan、SQL hash 和 `run_id`；
10. 数据刷新或模型失败时不伪成功、不覆盖最近成功结果；
11. 固定评测集达到获批阈值，所有 P0 回归用例通过；
12. 至少完成收入下降、毛利下降、设备/场站异常三个可复现案例；
13. 明确标注模拟数据、未生产部署、未有真实客户收益；
14. 项目负责人完成 Alpha 验收签署。

Alpha 周期从 DoR 通过且项目负责人正式授权 Phase 1 之日记为 T0，目标为 T0+30 个日历日。日期目标不替代上述质量门。

## 10. 真实性标签

对外和仓库内只能使用：

- 已设计；
- 已实现；
- 已测试；
- 已验证；
- 模拟数据；
- 规划中。

当前所有产品与技术能力的状态均为“已设计 / 待评审”或“规划中”，不能写成“已实现”。
