# V2 产品化 Backlog

> 冻结日期：2026-07-28
>
> 规则：P0 外需求不得中途插入主线；进入实施前必须补充业务价值、依赖、替换工时和验收标准。

## P0

- P0.0：Alpha 标签、远程备份、事实与证据、V2 执行基线；
- P0.1：公共产品框架、业务导航、设计 Token、状态与证据抽屉；
- P0.2：经营工作台和经营摘要；
- P0.3：收入、毛利、场站、设备专题差异化；
- P0.4：经营预警、可信 AI 分析、报告人工确认闭环；
- P0.5：CSV/Excel/PostgreSQL 数据接入 V1、映射、质量、发布和 charging_ops 场景包；
- P0.6：单客户私有化部署基线、备份恢复、监控、升级回滚和 RC 验收。

## P1

- MySQL Connector；
- 原生 DOCX/PDF 报告导出；
- SSO；
- 用户明确设置的长期偏好与记忆管理；
- 第二业务场景包；
- 更完整的审计/系统管理前端；
- 指标目标值与审批发布管理；
- 数据接入增量策略扩展。

## P2

- REST API 数据源；
- Kafka 与 CDC；
- Kubernetes 部署；
- 生产级共享多租户和高可用集群；
- 高级案例检索与受控 RAG；
- 更多复杂指标和预测模型（需单独口径评审）。

## 暂不实施

- 自由生成和执行任意 SQL；
- 多 Agent 编排或自主执行；
- 自动交易、自动设备控制；
- 自动邮件、企业微信和工单闭环；
- 无审批的组织级自动记忆；
- 跨租户共享记忆；
- 未经授权的真实企业数据接入；
- 与新能源经营分析无关的动画、3D 大屏或通用聊天能力。
