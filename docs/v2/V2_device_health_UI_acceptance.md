# V2 设备健康 UI 验收

## 目标与范围

- 目标：落地 Figma“设备健康优化版”页面，并保证 1600 × 900、浏览器 100% 缩放下一屏完整展示。
- 范围：设备筛选、六项健康概览、故障类型 Pareto、在线/离线趋势、维修优先级清单、设备详情、状态事件和分析处置流程。
- 非目标：不新增自动派单、自动维修、设备控制、自由 SQL 或跨系统执行能力。

## 数据与真实性

- 页面设备、场站、状态时长、状态事件、关联订单和关联收入来自受权限过滤的平台模拟数据库。
- 在线率和故障率来自已发布指标语义层。
- “模拟数据”、数据时间、来源和 `run_id` 压缩显示在顶部筛选栏右侧，不占用页面底部空间。
- 风险设备与订单、收入只表述为同期关联线索，不宣称设备异常造成经营损失。

## 数据库与安全影响

- 无数据库 Schema 或迁移变化。
- 新增只读 `GET /api/v1/dashboard/devices` 接口。
- 设备查询在读取事件、设备和会话前复用场站权限范围；区域经理仅能读取授权区域设备。
- 不包含密钥、真实连接串或真实企业数据。

## 验收证据

- 后端契约：`backend/tests/test_dashboard.py::test_device_dashboard_uses_simulated_database_and_enforces_region_scope`
- 前端一屏验收：`frontend/e2e/device-health.spec.ts`
- 截图：`docs/v2/evidence/ui/device-health.png`

## 限制与回滚

- 当前模拟状态事件只包含固定数据生成器提供的原因码，页面不虚构更细的故障分类。
- 回滚时可移除设备页组件、设备页样式、设备端到端测试和只读设备接口；无需执行数据库回滚。
