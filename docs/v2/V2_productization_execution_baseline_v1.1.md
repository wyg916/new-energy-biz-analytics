## 4. V2 P0 目标

1. 业务体验成熟：经营负责人进入首页 30 秒内识别经营状态、关键风险和优先动作。
2. 专题页面差异化：收入、毛利、场站、设备形成各自分析模型，不再仅换指标。
3. 可信能力不降级：技术证据可折叠，但 Query Plan、SQL Guard、Answer Guard、RBAC、审计和 run_id 完整保留。
4. 数据接入 V1：支持 CSV、Excel、PostgreSQL 的发现、映射、质量校验、试运行和发布。
5. charging_ops 场景包：抽离现有指标、维度、同义词、规则、问题集和报告模板。
6. 私有化部署基线：单客户独立实例、反向代理/HTTPS、备份恢复、监控、升级回滚和安装说明。
7. 交付周期：V2 P0 控制在 8—13 个有效开发日。

- MySQL、REST API 数据源、Kafka、CDC；

- 多 Agent、自动邮件、企业微信、工单闭环；
- 长期个人记忆、自动学习、跨团队共享记忆；
- 自由 SQL、任意数据库/任意字段万能问数；

- 大量新增指标或改变当前 15 项指标口径；
- 自动交易、设备控制或其他跨系统自动执行。

排除项进入 `V2_backlog.md`，不得中途插入 P0 主线。

## 8. 每阶段通用四道门禁

### 功能门禁

- 代码和交互真实存在，不以占位或静态 fallback 冒充；
- 所有业务数字来自 API、数据库或结构化计算；
- 页面状态覆盖成功、空数据、错误、延迟和无权限。

### 数据门禁

- 15 项指标口径、时间边界、权限范围和数据来源标签不变；
- 新数据接入必须经过映射、质量、试运行和发布；
- 数据库迁移可回滚，测试只使用专用 schema、事务回滚或阶段前缀测试表。

### 回归门禁

- 受影响测试先通过，再运行阶段回归；
- Query Guard 危险请求拒绝率保持 100%；
- Answer Guard 无依据业务数字保持 0；
- 不得删除、跳过或弱化测试。

### 证据门禁

- 保存命令、时间、退出码、通过/失败/跳过数量；
- 保存页面、API、数据质量和安全证据；
- README、阶段验收、限制和回滚说明与真实实现一致。

## 13. 停止条件

- 存在不可逆业务数据或数据卷风险；
- 需要真实凭据、企业真实数据或发现敏感信息泄露；
- 15 项指标口径与新需求无法兼容；
- Alpha 核心测试、安全或数据质量基线无法复现；
- 数据库迁移无法安全回滚；
- 当前分支存在无法安全保留或合并的用户修改；
- 需要突破本文件明确排除范围才能继续。

触发停止条件时只报告事实、已尝试方案、证据、推荐选择和最多三个确认问题。
