# 收入与订单 UI 开发验收

## 目标与范围

- 目标节点：Figma 文件 `HJIsXrJoPFZXhZFgSvAFOy`，节点 `1:2`。
- 落地范围：收入指标、收入趋势、收入驱动拆解、区域贡献、城市排名、收入时段热力图、重点下滑场站与经营洞察。
- 视口基线：浏览器 100% 缩放，`1600 × 900`，整页及卡片内部均不出现滚动条。
- 字体：统一使用 `Noto Sans SC / Microsoft YaHei / PingFang SC` 字体栈；可见正文最小字号不低于 `10px`。

## 数据与安全边界

- 所有经营数字来自已授权平台数据库中的固定种子模拟数据。
- 新增 `/api/v1/revenue/analysis` 只执行只读聚合，并在聚合前应用用户场站权限。
- 区域贡献合计必须与已发布 `charging_revenue` 指标对账一致。
- 经营洞察只引用页面结构化结果，设备与经营变化仅表述为关联或待核验，不宣称因果。
- 页面持续展示数据分类、数据时间、来源与 `analysis_run_id`。

## 非目标

- 不开放自由 SQL。
- 不引入外部真实数据、密钥或连接串。
- 不执行邮件、工单或跨系统动作。
- 不修改指标语义层定义与冻结产品范围。

## 自动验收

- `frontend`: TypeScript + Vite 构建通过。
- `frontend`: Vitest 格式化测试通过。
- `backend`: 收入分析接口事实聚合、权限过滤、元数据和 KPI 对账测试通过。
- `e2e`: 标题与主要模块可见；页面高度不超过视口；卡片无内部溢出；五行下滑场站无裁切；最小正文不低于 `10px`。
